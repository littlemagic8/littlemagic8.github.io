## **一、Grok Bot 是什么？**

Grok Bot 是 xAI 推出的 AI 执行型助手。官方把每一个 Bot 定义为一名可以长期协作的 AI teammate，也就是"AI 队友"。

它与普通 AI 对话最大的区别，是拥有一台持续运行的 **云端电脑** （还是一台 8核16G，硬盘 128 GB SSD的云电脑了！），预装 Chrome 浏览器、终端（Terminal）、文件管理器（Thunar）。获得授权后，它可以像人一样进入网站或应用完成工作，而不只是告诉你"应该怎么做"。

例如：

> 你是「AI 情报员」。请整理最近 7 天 xAI / Grok Bot 的重要更新。
>
> 优先来源：x.ai 官网与新闻、docs.x.ai/grok-bot、X 上 @bot。 输出中文表格：事件 | 大致时间 | 来源链接 | 一句话变化 | 对我有用行动建议。 区分「官方事实」和「你的推断」。 不要发布、转发、发邮件；只把草稿交给我确认。

接到任务后，Grok Bot 可以自行查找资料、保存链接、整理内容并输出成稿，不需要你一步一步指挥它点击哪里。

![image-20261018140850445](/img/2026-10-18-how-to-use-grok-bot/image-20261018140850445.png)

| 对比项       | 普通 AI（Grok 聊天等） | Grok Bot                               |
| ------------ | ---------------------- | -------------------------------------- |
| **记忆**     | 基本没有，聊完就忘     | 长期记忆，记住上下文和任务             |
| **持续性**   | 一次性对话             | 长期运行，能定时或触发自动干活         |
| **执行能力** | 主要是回答问题         | 有专属云电脑，能操作文件、浏览器、工具 |
| **工作环境** | 不连接你的真实账号     | 可接入邮箱、日历、GitHub、Notion 等    |
| **适用场景** | 问答、写作、搜索       | 反复执行的任务、监控、自动化流程       |

而且 Bot 是持久存在的。它可以逐渐记住自己的工作职责、常用文件、浏览器登录状态和你的输出偏好，不必每次都从零开始解释。

## **二、Grok Bot 可以用来做什么？**

更适合目标清晰、需要多步完成的工作。

### **0. 2026-10 官方能力速览**

- 独立邮箱：注册服务、联系商家、约时间
- Shopify 店务：查订单、库存、维护商品页
- 原生盯 X：产品反馈、突发新闻、行业周报
- **电脑任务更快**：官方称平均约快 3 倍
- **X 上 tag @bot 派活**、语音 / X Chat 增强

### **1. 自动查资料**

例如：

> 搜集最近 7 天 Grok Bot相关的重要更新，每条保留发布时间、原始链接和核心变化，最后整理成一份中文周报。

### **2. 处理文件**

你可以上传 PDF、表格、图片或其他资料，让它提取信息、做对比、整理重点。

例如：

> 总结这份 PDF 的 5 个核心结论，并单独列出所有日期、决定和待处理事项。每一项注明对应页码。

在获得授权后，它可以打开数据后台、CRM、邮箱或其他网页工具，读取信息并完成指定操作。

例如：

> 打开数据后台，对比本周与上月的新用户转化情况，找出变化最大的环节，并整理一份排查建议。不要修改后台数据。

- 行业调研 Bot

相比创建一个"什么都做"的万能助手，让每个 Bot 只负责一种明确工作，更容易积累有效的长期上下文。

> 我明明开通的是 SuperGrok，为什么页面上出现了 Cursor？

这是因为当前 Grok Bot 使用 Cursor 的账号认证和部分数据设置。官方同时支持符合资格的 SuperGrok 与 Cursor 套餐，出现 Cursor 登录字样并不代表你必须重新购买 Cursor 会员，**选择 Grok 账户进行授权登录即可**。

1. SuperGrok 是否已经在 Grok 账户中正常生效；

4. 回到 Access 页面重新检查资格；
5. 仍未识别时，通过官方支持入口反馈。

## **八、如何正确给 Grok Bot 分配任务？**

虽然 Grok Bot 可以理解自然语言，但任务写得越清楚，结果通常越稳定。

一个好任务 = **目标 + 来源 + 限制 + 交付物 + 确认节点**。第一次优先「读 / 整理 / 起草」，别一上来授权删除、支付、发布。

**派活模板：**

> 【角色】你是____。 【目标】最终交付：【来源】只看：（站点/文件/已连接应用）。 【限制】不要____；发送/发布/付款前必须先给我看全文。 【格式】用____（表格/Markdown/一页简报）返回。 【确认】做到____这一步停下等我确认。

再举两个高频场景：

**公众号选题调研：**

> 你是内容策划。围绕「Grok Bot 国内上手」找 5 个公众号选题。 每条：标题备选 2 个 | 目标读者 | 核心角度 | 建议结构（小标题）| 需要的素材来源。 不要发布、不要发朋友圈；选题表交给我挑。

这里最后一句非常重要。**第一次使用时，建议先让 Bot 做"读取、整理、起草"类工作，不要一开始就授权它直接删除、支付、发布或发送消息。**

**会议纪要 → 待办：**

> 我上传了会议录音转写/笔记。请整理：决议 | 负责人 | 截止日 | 未决问题。 输出表格 + 给我本人的 3 条下一步。 不要发纪要给参会人；先给我确认。

## **九、云电脑、Take Over、Skills 和 Routines**

### **1. 云端电脑**

Grok Bot 拥有持续运行的云端电脑（全天候 24 小时运行），可以使用浏览器、文件系统、终端、Plugins 和 MCP。即使你暂时离开电脑，已经分配的任务也可以继续在云端运行。

需要特别注意：同一账号下的多个 Bot 会共享这台云电脑，也会共享里面的文件、浏览器 Session 和网站登录状态。因此，不能把不同 Bot 当作互相隔离的安全空间。

### **2. Take Over：需要登录时由你接管**

当 Bot 打开的网站需要密码、Passkey、两步验证码或 CAPTCHA 时，它会提示你接管电脑。

正确操作方式是：

1. 打开对话中的 Agent Computer；
2. 点击 Take Over 接管；
3. 自己输入密码、验证码或完成 CAPTCHA；
4. 完成后把控制权交还给 Bot；
5. 告诉它继续执行。

> **不要把密码或一次性验证码直接发送在普通聊天窗口中。**

### **3. Skills：复用成功的工作流程**

当某项工作已经跑通，可以让 Bot 把操作过程保存成 Skill。

例如：

> 把刚才整理 AI 周报的方法保存成一个 Skill，名称为"AI 周报整理"。保留信息来源、筛选标准、输出格式，以及任何发布操作都必须经过我确认的规则。

Skill 更像一套可重复使用的标准操作方法。

### **4. Routines：让任务按计划自动运行**

Routine 用来规定某个 Bot 在什么时间或条件下执行工作，例如：

- 每天早上整理行业新闻；
- 每周一生成运营周报；
- 定期检查后台数据；
- 每晚汇总当天的客户反馈。

比较稳妥的使用顺序是：**先手动完成一次任务 → 调整到稳定 → 保存为 Skill → 最后再设置 Routine。**

## **十、Grok、Grok Build 和 Grok Bot 有什么区别？**

这三个产品很容易被混在一起，其实定位并不相同。

| 产品       | 主要定位           | 更适合的任务                         |
| :--------- | :----------------- | :----------------------------------- |
| Grok       | 通用 AI 助手       | 问答、写作、分析、图片和日常创作     |
| Grok Build | AI 编程 Agent      | 写代码、修改项目、运行命令和开发软件 |
| Grok Bot   | 通用执行型 AI 队友 | 跨网页、应用和文件完成完整工作       |

可以简单理解为：

> **Grok 帮你想，Grok Build 帮你写代码，Grok Bot 帮你把工作真正做完。**

Grok Bot 能做的事情非常广，你可以让他去给你注册 Claude、ChatGPT 账号、给你做 MV 视频都行。

## **十一、使用 Grok Bot 前，建议先做好这些安全设置**

Grok Bot 能真正操作工具，因此权限边界比普通聊天更加重要。

建议在任务中明确写出：

> 任何发送消息、发布内容、购买付款、删除文件、修改权限和生产环境变更，都必须先向我展示具体内容并获得确认。

同时注意以下几点：

- 第一次使用时，优先安排只读或起草类任务；
- 只连接当前工作真正需要的应用；
- 密码、验证码和付款确认自己接管完成；
- **重要操作优先选择 Allow once，不要随意设置 Always allow；**
- 不再使用某个网站时，及时退出登录或撤销授权；
- 定期检查已经启用的 Plugins、Skills 和 Routines；
- 对重要结果要求保留链接、截图或操作记录。

AI 可以代替你执行操作，但最终权限仍然应该由你掌握。但在日常使用时，我觉得没有什么重要的东西，也相信 AI，我大部分都设置为 Always allow，他就一直运行，我只需要看到结果就行。

## **十三、Grok Bot 进阶使用技巧（实战经验总结）**

最后分享一批来自官方文档和社区实战的使用技巧，帮你把 Grok Bot 用得更稳、更省：

### **1. 一个 Bot 只给一个岗位**

官方 Bot 指南和大量玩家实践都指向同一条经验：**角色越聚焦，Bot 的记忆越准、输出越稳**。不要创建一个"帮我做任何事"的万能助手，而是按岗位拆分（如：每日站点巡检 Bot、客服草稿 Bot、周报 Bot），每个 Bot 围绕固定的工作、来源、工具、审批边界来写 Description。

### **2. 记住黄金自动化流程**

想让任务长期自动跑，一定按这个顺序来：

> 手动跑通一次 → 修正指令 → 保存为 Skill → 换个输入再测一次 → 创建 Routine → 先 Test run 盯完全程 → 再启用定时。

不要把第一次"跑得还行"的结果直接存成 Skill——你要保存的是一套稳定可复现的方法，而不是一次碰巧成功的对话。

### **3. 省额度的几个实用习惯**

- **优先用 Plugins / 连接器，少用浏览器**：插件一次调用就能返回结构化数据，浏览器操作要反复截图点击，后者消耗额度明显更多；
- **Routine 别设太高频**：每 15 分钟跑一次等于每天 96 次，每次都耗额度。监控类任务优先用事件触发（如收到邮件、GitHub 有更新），没有事件就用每天 1~2 次的定时；
- **一次性任务用完就删**：比如盯一场发布会、盯一次促销的临时 Routine，结束后记得删除，否则它会一直"醒来发现没事做"照扣额度；
- **周期任务用独立的新 Bot**：长对话上下文会让每次运行都更贵，别把自动化例行任务挂在聊天记录很长的主力 Bot 上。

### **4. 审批规则的正确用法**

新工作流一律用 **Allow once**；跑稳定之后，只对"读取类"操作（打开某后台、读某面板、写 /workspace 文件）设置 Always allow；而发送、发布、支付、删除这类对外操作，永远保留 **Require Approval**。当 Always allow 和 Require Approval 规则同时命中时，后者优先级更高，可以用这个特性做"白名单 + 红线"的组合。

### **5. 敏感信息永远不走聊天框**

遇到密码、两步验证码、CAPTCHA，用 Take Over 接管自己输入；接入应用需要 API Key 时，走连接器的专用密钥输入框（有遮罩、不进入对话记录），**绝对不要把密码、验证码或 .env 文件内容粘贴到聊天窗口**。

### **6. 重要文件放 /workspace，并及时另存**

Bot 云端电脑上，临时目录、未同步状态在故障恢复时可能丢失，官方建议把持久工作放在 `/workspace` 下。真正重要的产出（报告、数据、代码）再复制一份到你的仓库、网盘或知识库中，云端电脑当作"工作电脑"而不是"归档库"。

### **7. 多 Bot 协作的正确姿势**

- 群聊支持 2~6 个 Bot，适合想直观看到 Bot 之间交接过程的场景；
- 但顺序性流程更推荐**只发给一个 owner Bot**，让它去调用其他 Bot 并汇总结果，避免群里多个 Bot 互相重复讨论、空耗额度；
- 已保存的 Skills 在你所有 Bot 之间通用（在 Settings → Plugins → Yours 里启用）。

### **8. 让 Bot "跟着你学"**

官方推荐的高效教学方式：下次你手动做这类任务时，让 Bot 跟着看一遍（follow along / Teach a task），它会观察你的操作步骤，记住你的偏好，并生成技能草稿供你审核修改。这比自己从零描述工作流更省事。

### **9. 隐藏 Bot ≠ 停止工作**

把 Bot 从侧边栏隐藏只是不显示而已，它和它的 Routine 可能仍在后台运行消耗额度。想真正停下，要单独暂停或删除对应的 Routine。

### **10. 善用手机端**

手机端可以随时派活、语音下单、拍照/截图丢给 Bot、审批请求和查看云端电脑进度——把手机当作"给队友发微信"的入口。但编辑 Routine 计划、测试/删除例行任务、教学浏览器工作流这类管理操作，还是要回桌面端完成。
